A documented gap between account and decision

In an October 2026 public case study, a fintech startup examined AI-assisted software development and its review controls. During a defined enforced period, 263 non-bot merges into the main branch satisfied the recorded non-author approval and required-check conditions. For 71 of those merges, the only qualifying approval was submitted by an agent session through the technical lead's account. The platform record showed the lead's account. The underlying session evidence identified automation.

71 / 263About 27% in one study's defined sample

This figure describes one startup and one time period. It is not a cross-industry failure rate. It does not establish that the approved changes were defective. It illustrates why account identity and decision authority require separate evidence. Read the original study.

The same distinction applies to an AI-assisted supplier approval, purchase order, bank-detail change or operational exception. A workflow might be well designed while its audit trail still leaves the decisive question unanswered.

PrismBay's A-D-E decision evidence test

Use three separate questions before accepting an AI-assisted approval record. This practical teaching model is not a certification or a substitute for legal or regulatory assessment.

A · ACTOR

Which human or software identity executed each action, through which authenticated session and tool?

D · DECISION

Who or what had authority to approve the action, and what were the delegation limits?

E · EVIDENCE

Which exact version, policy checks and approval existed before execution?

Five evidence checks before live deployment

CHECK 01

Identify the executing actor

Record the dedicated agent or human identity, session ID, tool, action and timestamp. Avoid treating a shared human login as proof of human execution. Test: Can you distinguish an automated action from a manual one in the log?

CHECK 02

Record decision authority separately

Identify the recommendation author, checker and final authorizer. If the approval is automated, state the delegation rule and ceiling. If a person approves, capture a genuine decision event tied to the evidence presented. Test: Can an auditor identify the decision-maker without guessing from the account name?

CHECK 03

Bind approval to the exact version

Record the approved commit or transaction payload. In procurement, bind the supplier, beneficiary account, amount, currency and document revision to the approval. Test: Does changing one beneficiary digit invalidate the earlier authorization?

CHECK 04

Enforce the same policy on alternate routes

List normal user flows, API calls, bulk imports, emergency procedures and administrative paths. Confirm each consequential action encounters an enforceable gate. Test: Does a prohibited action fail through every route, not only the main screen?

CHECK 05

Preserve exception and denial evidence

Capture the reason, named owner, expiry, authorization and result for every exception. Preserve denial events and independent review of bypasses. Test: Does an expired approval or missing reviewer create a visible denial and escalation?

A fictional payment pilot: the one-digit test

An agent matches a fictional $8,400 invoice to a purchase order and prepares a recommendation. A person reviews the supplier, beneficiary account, amount, supporting evidence and policy result. The system records authorization for that exact version. A separate execution service checks the authorization before any payment.

Measure the share of transactions with complete actor, decision and version evidence, plus correctly denied test attempts. Count exceptions and review time. Treat faster processing without reliable approval evidence as an incomplete result.

Put the checks into your operating process

Start with one workflow, one named owner and one consequential action. Map the allowed identities and execution routes. Run the one-digit test and one bypass test. Record the outcome before increasing autonomy. For broader readiness, use the existing free five-gate assessment.
